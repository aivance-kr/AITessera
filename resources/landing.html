개요

보호된 API 는 Authorization: Bearer 토큰이 필요합니다. 이 페이지와 아래 엔드포인트는 인증 없이 열람할 수 있습니다.

목적

중앙 집중 인증·인가

가입·이메일 인증·로그인·토큰 갱신·로그아웃·회원 관리를 하나의 API 로 제공해 각 서비스가 인증을 직접 구현하지 않도록 합니다.

원칙

검증된 라이브러리 위임

JWT·암호화 같은 보안 핵심은 직접 만들지 않고 lcobucci/jwt 등 신뢰받는 라이브러리에 맡깁니다.

대상 서비스

AIvance 제품군

aicura · aicopia · aicreo · aivance · ailicet. 소속(서비스)별로 계정을 구분하며 이메일 중복은 소속 단위로 판단합니다.

구현 내용

현재 API 에 구현된 기능과 보안 설계입니다.

인증

Access / Refresh 토큰

  • Access 토큰 15분, Refresh 토큰 14일
  • Refresh 토큰 회전(rotation)과 폐기(로그아웃)
  • 토큰 헤더에 kid(RFC 7638) 포함
보안

JWT 검증 제약

  • SignedWith 로 서명 알고리즘 고정 → alg:none 우회 차단
  • StrictValidAt 로 iat·nbf·exp 모두 검증
  • 만료는 TOKEN_EXPIRED 로 구분 응답
인가

회원구분 기반 접근 제어

  • 운영자 / 대행사 / 일반회원 — JWT role 클레임
  • 자가가입은 항상 일반회원
  • 운영자 전용 엔드포인트는 #[RequireRole] 어트리뷰트 + RoleGuardMiddleware
계정

가입 · 이메일 인증

  • 자가가입 후 이메일 인증 코드 확인 · 재발송
  • 비밀번호 정책(최소 10자) · 해시 저장
  • 본인 조회·수정·탈퇴(/me)
  • 운영자의 회원 목록·상세·수정 및 계정 생성
방어

레이트 리밋

  • Redis 기반 슬라이딩 윈도우 (1분)
  • 로그인·가입·인증 등 민감 경로는 엄격 정책
  • 초과 시 429 + Retry-After
연동

JWKS 공개키 배포

  • RS256 전환 시 공개키를 JWKS(RFC 7517)로 자동 제공
  • 외부 서비스가 키를 내려받아 토큰 검증 · 키 회전 대응
  • HS256 에서는 시크릿을 노출하지 않고 빈 키셋 반환
비동기

Redis 큐 & 워커

  • 클라이언트 로그 수집(POST /logs) → 즉시 202 후 큐 적재
  • 메일 발송 · 로그 처리 CLI 워커
  • 요청 사이클에서 무거운 작업을 분리
모니터링

로그인 이상 탐지 · 리포트

  • 로그인 이벤트 스코어링(규칙 + Claude)
  • 임계값 초과 시 쿨다운을 둔 실시간 알림 메일
  • 일일 로그·보안 리포트를 AI 서술로 메일 발송 (AI 불가 시 통계 폴백)
문서

OpenAPI 자동 생성

  • PHP 어트리뷰트에서 스펙을 생성 (swagger-php v5)
  • RapiDoc UI — 좌측 API 목록, Try-it-out, bearerAuth 지원
  • 공통 ErrorResponse 스키마로 에러 규약 통일

아키텍처

프레임워크 대신 PSR 표준 라이브러리를 조합합니다. 웹에 노출되는 진입점은 public/index.php 하나입니다.

ErrorHandler→TrailingSlash→Cors→RateLimit→JwtAuth→RoleGuard→RouteDispatch 
Request → PSR-15 middleware pipeline (Relay)
        → Controller   입력 검증 → 서비스 호출 → 표준 응답   (얇게 유지)
        → Service      비즈니스 로직 · 트랜잭션
        → Repository   PDO prepared statement 전용 데이터 접근
        → PSR-7 Response

의존성은 PHP-DI(PSR-11) 생성자 주입으로만 연결합니다.

계층 분리

Controller / Service / Repository / Middleware / Domain(DTO·enum) / Support 로 책임을 나눕니다. 컨트롤러·서비스에서 SQL 을 직접 실행하지 않습니다.

표준 응답 · 에러 규약

{status, data, meta} 성공 응답과 {status, code, message} 에러 응답. 도메인 예외가 HTTP 상태와 에러 코드를 함께 지닙니다.

시간대 규약

DB 는 UTC 로 저장하고, 애플리케이션·화면은 Asia/Seoul(KST)로 다룹니다.

적용 기술

모든 의존성은 Composer 로 관리하며 PSR-4 오토로딩을 사용합니다.

자주 묻는 질문

AITessera 는 무엇인가요?

AITessera 는 AIvance 제품군을 위한 JWT 기반 인증·인가 REST API 입니다. 가입, 이메일 인증, 로그인, 토큰 갱신, 로그아웃, 회원 관리를 하나의 API 로 제공해 각 서비스가 인증을 직접 구현하지 않도록 합니다.

어떤 토큰을 발급하나요?

수명이 짧은 Access 토큰(15분)과 수명이 긴 Refresh 토큰(14일)을 발급합니다. Refresh 토큰은 갱신할 때마다 회전하며 로그아웃 시 폐기됩니다. 서명 알고리즘은 HS256 또는 RS256 으로 고정해 alg:none 우회를 차단합니다.

다른 서비스는 토큰을 어떻게 검증하나요?

RS256 으로 운영할 때 공개키를 JWKS(RFC 7517) 형식으로 /.well-known/jwks.json 에서 인증 없이 제공합니다. HS256 에서는 시크릿을 노출하지 않고 빈 키셋을 반환합니다.

어떤 회원 구분을 지원하나요?

운영자, 대행사, 일반회원 세 가지 역할을 지원하며 JWT 의 role 클레임으로 접근을 제어합니다. 자가가입은 항상 일반회원으로 생성됩니다.

API 문서는 어디서 볼 수 있나요?

/api/docs 에서 Swagger 기반 API 문서를, /api/v1/openapi.json 에서 OpenAPI 스펙을 인증 없이 확인할 수 있습니다.
